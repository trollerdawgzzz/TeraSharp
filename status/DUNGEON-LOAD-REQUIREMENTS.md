# T189 — Dungeon load requirements

Research date: 2026-09-23. Worktree: `TeraSharp-cowork`, branch `cowork/T8`, base `ee131c1`. **Research/checklist only: no server code, datasheets, client DC, deployment, or T177 script was changed.**

A new dungeon is a reference graph, not a fixed bundle of mandatory `_zone.xml` files. The core is a continent/map registration plus a dungeon template; encounters, matching, Vanguard, rewards, transport, rankings and client presentation add their own references. An absent optional row and a present row pointing at missing data have different outcomes. This checklist separates those cases rather than calling every feature a boot prerequisite.

The concrete control is continent/dungeon **9781**, hunting zone **781**, map **Velik_Palace_DG_P**, matching role **17**. Substitute **C** for the new continent/dungeon ID, **H** for the new hunting-zone ID, **R** for its matching role, **P** for an independently allocated path/teleport/menu key. Numbers in different namespaces are not interchangeable. `AreaData_<C>_<area>.xml` uses the **continent** in its filename; AreaList's `Zone@x,@y` are tile coordinates, not H.

**Failure vocabulary:** `load/validation error` means the cited loader returns false or increments its error counter; `continent-load failure` means map/instance initialization returns false; `optional/silent omission` means no mandatory per-C/H presence check was found and the feature has no new row; `unknown` means the failure path was not established. Do not convert an unknown into a promised silent fallback. For wildcard families, the engine iterates discovered files; it does not invent a required filename for every H (W197438–198147).

The World error mechanism is explicit: `FUN_140028520` increments the thread's load error count (W28628–28633); `FUN_140028540` / `FUN_140028660` count failed loader/validator returns (W28640–28698). `DatasheetManager::Validate` invokes Dungeon, ClassException, BossGage, Retry and Work validators and returns whether that count is unchanged (W643559–643641,643681–643688). This proves a validation error, not a universal process-crash behavior for every malformed sheet. Arbiter and Match startup gates are cited in their checklist below.

## 1b. World — NPC, spawn, reward and transport closure

- `DataXmlManager::LoadEachFile`, W197438-198147, walks configured existing files and accumulates callback failures (success initially true at197452, changed on failed callbacks at198117-120). It does **not** synthesize a required `_new Hone.xml` filename for each new continent. A missing unreferenced per-zone file is not itself a cross-reference error. A discovered malformed file or loaded row referring to a missing required template can fail loading/validation.
- Loaded NPCs, AI, boss-gauge entries and some action checks are filtered to hosted hunting zones: e.g. `AiDataSheet::Validate` W2284377-4380; `BossGageDataSheet::Validate` W1766741-6744. Validate on each World that actually hosts the new continent.
- `TerritoryDataSheet::ValidateNpcSpawnTemplate` W3451840-3452175 resolves `(npcTemplateId, huntingZoneId)` and reports a missing NPC at3451902-1924. `AiDataSheet::Validate` W2284368-2284463 resolves each relevant NPC's `(huntingZoneId, aiid)`; missing AI at2284382 increments the validation error count. Detailed AI-work validation is W2282808-2284337 (skill/template/owner mismatch message W2283328-3332). Presence of a whole zone file is not equivalent to complete referenced rows.

## 2–3. Arbiter and MatchServer — actual consumers

- Arbiter `DatasheetManager::PreLoad`: AreaList, DungeonMatching, DungeonWorkData, ContinentData and World Structure (A085:14482–14670). - Match `DatasheetManager::PreLoad` loads **AreaList, DungeonMatching, ContinentData** (M:129597–129734). `Load` invokes **BattleFieldTemplate, DungeonDataSheet, MatchingRuleDataSheet** (M:129753–129772). Failed PreLoad/Load/Validate blocks normal startup before Arbiter-session setup (M:206463–206514).
- CFG:521–533 lists 13 Match configuration entries, but this is **not proof all 13 are loaded**. In particular no EventMatching, FieldEvent, FieldTemplate, WorldParameter/WorldData reader was found in M; no new per-dungeon rows in those sheets can be claimed required by MatchServer from the inspected startup path. DailyEvent loader code exists (M:30167–30192), but a dungeon-specific requirement or startup caller was not established. Keep shared configured files; do not manufacture mandatory per-dungeon rows from config names.
- In the tables, “load error” means the cited parser reports/increments a load-error count or returns failure, propagated by the above startup gate. It does not mean every missing optional row fails boot. No destructive missing-file boot experiments were run.

## 7. Completion checklist for an actual new dungeon

- [ ] Allocate collision-free C/H and any genuinely new role/event/quest/menu/path keys; maintain an explicit old-to-new mapping by namespace.
- [ ] Complete the applicable file rows above. For any new reference, either prove its existing target is intentionally shared or supply the matching new target. Find files by XML ownership and reference values, including global lists and scripts.
- [ ] Verify server sheet versions and effective roots on **Arbiter, Match, Topography and every owning World**. A shared local folder does not prove deployed consistency; a nonowning World may skip validation.
- [ ] Verify geometry/path assets; rebuild producer shared-memory state and confirm the new continent initializes on its World. Confirm routing/link readiness separately.
- [ ] Use a matching repacked client DC and retain real cooked assets for every referenced map/shape/action/UI package. Existing packages can be reused; a new area name cannot create geometry.
- [ ] Confirm native load/validation logs have no errors; then test entry/exit, section/recall, NPC spawn and AI, scripted boss phases, completion/loot, reset/re-entry, matching, Vanguard and any selected optional feature. Record which features were intentionally omitted.
